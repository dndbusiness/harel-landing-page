# oshsim — סימולציה לדפי עו"ש (כלי ליועץ פיננסי)

כלי מקומי: קולט דפי חשבון של לקוח, מפרק לתנועות, מאמת מול היתרות שבדף, מזהה
תנועות קבועות, ומריץ תרחישי "מה אם". הפלט: Excel עם נוסחאות חיות, סימולציה
בפורמט דף עו"ש (HTML/PDF) עם סימון "סימולציה — אינו מסמך בנקאי", ודוח השוואה.

המפרט המלא נמצא ב-`SPEC.md`. כאן: איך מריצים, מה בנוי, ומה עוד חסר.

## גרסת דפדפן (Artifact ב-claude.ai)

`web/` הוא אותו מנוע ב-JavaScript, כאפליקציה בעמוד אחד: העלאת PDF/CSV, ולידציה, תור סיווג,
פרמטרים, בניית תרחיש, תוצאות, דף מדומה ושמירה כ-Excel. הקבצים נקראים בדפדפן בלבד.
סכומים באגורות שלמות, וריבית מצטברת ב-BigInt, בלי float.

```bash
python3 web/build.py             # כותב web/osh-simulator.html לפרסום
node web/test_engine.js <synthetic.csv>   # משווה למנוע ה-Python (py_expect.json)
```

לא כלול בגרסת הדפדפן: מחשבון ברוטו→נטו, הצפנה במנוחה ומחיקה מסודרת (אין שמירת נתונים בכלל).

## התקנה

```bash
cd simulator
pip install -r requirements.txt
# אופציונלי: LibreOffice (בדיקת נוסחאות ה-Excel), Chromium (PDF של הסימולציה)
```

## עבודה עם לקוח

```bash
export OSHSIM_KEY=$(python3 -m oshsim keygen)   # שומרים את המפתח מחוץ לתיקיית הלקוח
mkdir -p data/client1
cp config/params.example.yaml data/client1/params.yaml   # ממלאים עמלה/ריבית/מסגרת עם מקור

python3 -m oshsim ingest   --client data/client1 path/to/statement*.pdf
python3 -m oshsim review   --client data/client1                         # תור אישור קטגוריות
python3 -m oshsim review   --client data/client1 --approve <TXN_ID> "דיור/משכנתה" "חשבונות"
python3 -m oshsim patterns --client data/client1                         # קבועות + כללי שישי/שבת לכל מנפיק
python3 -m oshsim simulate --client data/client1 scenarios/salary_up_10.yaml --pdf
python3 -m oshsim purge    --client data/client1 --yes                   # מחיקה בסיום
```

`ingest` עוצר עם דוח פערים (יום, צפוי, בפועל, הפרש) אם הדף לא מתיישב. `simulate`
מריץ קודם תרחיש ריק ועוצר אם הוא לא זהה לדף לאגורה, ורק אז מריץ את התרחיש.

כש-PDF של בנק לא נשלף נכון: `python3 -m oshsim inspect file.pdf` מציג את המילים
והעמודות שזוהו. אפשר גם להזין תנועות ב-CSV (`date,value_date,description,amount,balance,reference,channel`),
והן עוברות את אותה ולידציה.

## תרחישים

קובץ YAML לכל תרחיש (דוגמאות ב-`scenarios/`). סכומים נכתבים כמחרוזת (`"500.00"`).

| `type` | מה עושה | שדות |
|---|---|---|
| `change_amount` | שכר/הוצאה גבוהים או נמוכים | `select`, `pct` או `amount`, `start`, `end`, `basis: net/gross`, `gross_monthly` |
| `remove` | ביטול הוראת קבע/מנפיק | `select`, `start`, `end` |
| `add_recurring` | הוראת קבע חדשה | `description`, `amount`, `day_of_month`, `channel`, `friday_rule`, `closed_rule` |
| `one_off` | אירוע חד-פעמי | `date`, `amount`, `description` |
| `loan_schedule` | פירעון/מחזור הלוואה | `select`, `start`, `schedule_csv` (מהלקוח), `payoff_amount` |
| `rate_change` | טבלת ריבית חלופית | `rates` |

`select` בוחר שורות לפי `category`, `subcategory`, `description` (regex), `recurring_id`, `direction`.
`mode: forward` עם `forward_months` מקרין קדימה לפי הדפוסים, והפלט מסומן כהערכה.

## איך מחושבות העמלות והריבית בתרחיש

בהיסטוריה, כל שורת עמלה או ריבית נשארת מעוגנת בסכום שנרשם בפועל. התרחיש מוסיף
רק את ההפרש שהמודל מחשב:

- **עמלת ערוץ ישיר:** `תעריף × (פעולות (י) בחודש − מכסה)`. האסמכתה בשורת העמלה היא
  המונה האמיתי (גם כשהדף מתחיל באמצע החודש). הסרה או הוספה של פעולת (י) משנה
  את העמלה של החודש הבא.
- **ריבית:** `Σ יתרה יומית × שיעור ÷ 365`, יום אחר יום, כך ששינוי ביתרה משנה ריבית,
  והריבית משנה את היתרה. בלי שיעור בקובץ הפרמטרים הריבית נשארת כפי שנרשמה,
  והפלט אומר זאת במפורש.

כך תרחיש ריק זהה לדף לאגורה גם כשהמודל לא מושלם. איכות המודל מוצגת בנפרד בכיול:
עמלה (מודל מול כל שורת עמלה) וריבית (מודל מול כל חיוב, עם אחוז טעות). כשטעות הכיול
עוברת את הסף, או כשאין תקופה מלאה לכייל עליה, הריבית מסומנת "הערכה".

## מה עוד חסר או דורש החלטה

- **הדף האמיתי.** המפרק נכתב לפי המבנה שתואר במפרט ונבדק על PDF סינתטי. לפני שימוש:
  `OSHSIM_GOLDEN_PDF=/path/statement.pdf python3 -m pytest tests/test_golden.py`.
  אם ייכשל, `inspect` יראה מה שונה בפריסה.
- **ימי סגירה שאינם יום-טוב** (יום העצמאות, ערבי חג לפי נוהל הבנק) לא נכתבו מהזיכרון.
  ממלאים ב-`config/calendar.yaml` ממקור הבנק.
- **מחשבון ברוטו→נטו** בנוי ללא מספרים. ממלאים `config/tax/<שנה>.yaml` ממקור רשמי
  (תבנית ב-`TEMPLATE.yaml`). עד אז הקלט בנטו.
- **הצעת קטגוריה ממודל שפה:** יש נקודת חיבור (`ExternalModelSuggester`) שחסומה בלי
  הסכמה מפורשת. ברירת המחדל היא הצעה מקומית לפי דמיון לתנועות שכבר סווגו.
- **דפי אשראי:** עוד לא נקלטים. שינוי בחיוב כרטיס הוא שינוי בחיוב הכולל, והפלט אומר זאת.
- **ריבית בהקרנה (Forward):** נרשמת בחודשים שמוגדרים בפרמטרים (`forward_posting_months`),
  לא נלמדת מההיסטוריה.
- **מחיקה מסודרת** דורסת ואז מוחקת, אבל בדיסקי SSD אין לזה ערובה מלאה. ההגנה העיקרית
  היא ההצפנה במנוחה (`OSHSIM_KEY`).
- שאלות פתוחות ליועץ (סעיף 12 במפרט) עדיין פתוחות. ברירות המחדל: שכר בנטו, Excel + HTML.

## בדיקות

```bash
python3 -m pytest -q
```

הבדיקות רצות על דף סינתטי (`tests/fixtures/synthetic.py`, שמות וסכומים מומצאים):
ולידציה ודוח פערים, PDF מול CSV, קבצים חופפים, שורות זהות באותו יום, זהות, מונוטוניות,
עמלה (כולל 35/45/36 → 61.60/79.20/63.36), ריבית וכיול, Forward, Excel מול LibreOffice,
סימון בכל עמוד PDF, הצפנה ומחיקה, ובדיקה שאין `float` במסלול הכסף.
